# INNOVFIX Internal Messenger — Firebase backend

This directory contains the Firebase-only backend for the Android package
`com.jp.whatsappclone`. It is local-first on Android: Room remains the UI source
of truth, while Firestore synchronizes messages and Cloud Functions maintains
inbox summaries and FCM notifications.

The repository intentionally does not bind itself to a live Firebase project.
Copy `.firebaserc.example` to `.firebaserc` only after the project exists.
`.firebaserc`, ADC files, service-account keys, generated JavaScript, local
environment files, and Firebase emulator state are ignored by Git.

## Production project checklist

1. Create a Firebase project with display name **INNOVFIX Internal Messenger**.
   Keep the generated unique project ID; do not try to reuse the display name
   as an ID.
2. Upgrade it to Blaze and configure billing budget alerts plus alerts for
   Firestore reads/writes, Functions failures, and spend. Billing and budget
   alerts are console/IAM operations and are not created by this repository.
3. Create the default Firestore database in `asia-south1`. Deployed second-
   generation Functions also default to `asia-south1`.
4. Enable Anonymous Authentication, Cloud Firestore, Cloud Messaging,
   App Check with Play Integrity, Crashlytics, and Performance Monitoring.
   Cloud Storage is deliberately not used in messaging v1.
5. Register the Android app as `com.jp.whatsappclone` and put the downloaded
   `google-services.json` in `app/`. Never commit a hand-created replacement.
6. Copy `.firebaserc.example` to `.firebaserc` and replace its placeholder with
   the generated project ID.
7. Install current Firebase CLI tooling, then install and build both Node
   packages:

   ```powershell
   npm.cmd --prefix backend/functions install
   npm.cmd --prefix backend/functions test
   npm.cmd --prefix backend/admin install
   npm.cmd --prefix backend/admin test
   ```

8. Deploy the security policy and Functions:

   ```powershell
   firebase deploy --only firestore:rules,firestore:indexes,functions
   ```

   Keep `ENFORCE_APP_CHECK=false` during the five-person metrics pilot. Put the
   value in the project-specific Functions environment (never in a committed
   `.env`), change it to `true`, and redeploy the callable before broad rollout.

9. Enable the two TTL policies (enablement can take time and TTL deletion is
   intentionally not immediate):

   ```powershell
   .\backend\scripts\configure-ttl.ps1 -ProjectId YOUR_PROJECT_ID
   ```

   The `typing.expiresAt` policy cleans stale presence hints. Clients must still
   ignore typing records older than ten seconds because Firestore TTL deletion
   can lag. `functionEvents.expireAt` keeps trigger idempotency records for
   seven days.

## Firestore contract

The single organization ID is `innovfix`.

| Path | Server/client-owned fields |
| --- | --- |
| `organizations/innovfix/members/{uid}` | `email`, `displayName`, `role`, `active`, nullable `avatarKey`, `notificationPreference`, nullable `lastSeenAt`, nullable `activeUntil`, `createdAt`, `updatedAt` |
| `members/{uid}/devices/{installationId}` | `installationId`, `token`, `platform`, `enabled`, `createdAt`, `updatedAt` |
| `members/{uid}/inbox/{conversationId}` | `conversationId`, `orgId`, `conversationType`, `title`, nullable `lastMessageId`, `lastMessagePreview`, nullable `lastMessageSenderId`, nullable `lastMessageAt`, `unreadCount`, `muted`, `pinned`, `updatedAt` |
| `conversations/{conversationId}` | `orgId`, `type`, `memberIds`, nullable `title`, `createdBy`, `createdAt`, `updatedAt`, `schemaVersion` |
| `conversations/{conversationId}/members/{uid}` | `userId`, `role`, `joinedAt`, `lastDeliveredAt`, `lastReadAt`, `updatedAt` |
| `conversations/{conversationId}/messages/{uuidV7}` | `senderId`, `text`, `clientCreatedAt`, `serverCreatedAt`, nullable `replyToMessageId`, nullable `deletedAt`, `schemaVersion` |
| `conversations/{conversationId}/reactions/{messageId_uid}` | `messageId`, `userId`, `emoji`, `createdAt`, `updatedAt` |
| `conversations/{conversationId}/typing/{uid}` | `userId`, `isTyping`, `expiresAt`, `updatedAt` |

Message IDs are lowercase UUIDv7 values generated by the Android client.
Messages contain 1–4,000 characters. The supported reaction set is
`👍 ❤️ 😂 😮 😢 🙏 🫡 😊`. Delete-for-everyone is a soft delete: only the
sender sets `deletedAt` and clears `text`; ordering metadata remains.

Receipts are monotonic watermarks on each conversation membership document.
`lastReadAt` never exceeds `lastDeliveredAt`. A new membership initializes both
to the Unix epoch.

## Callable and trigger behavior

The Android SDK calls the regional callable:

```text
getOrCreateDirectConversation
request:  { targetUserId: string }
response: { conversationId: string, created: boolean }
```

It requires a valid Auth token with `orgId: "innovfix"` and two active employee
profiles. App Check is observed without rejection during the metrics pilot and
is enforced after `ENFORCE_APP_CHECK=true` is deployed. The callable hashes the
sorted employee IDs and organization
ID into a deterministic conversation ID, then transactionally creates the
conversation, memberships, and initial inbox documents. Concurrent calls return
the same conversation.

The Android app has no login form. On first launch it signs in through Firebase
Anonymous Authentication and calls `bootstrapAnonymousMember`. The callable
accepts only an anonymous Firebase identity, creates that identity's active
INNOVFIX directory profile, assigns the `orgId: "innovfix"` and `MEMBER` claims,
and idempotently provisions `ayush@innovfix.in` as the initial test contact.
Firestore clients still cannot create employee profiles or assign claims.

Anonymous identities are suitable only for the current closed testing phase.
Before public distribution, replace anonymous bootstrap with an administrator-
approved enrollment mechanism or restrict the callable with a server-managed
allow-list, enable App Check enforcement, and remove the test-contact bootstrap.

`onMessageCreated` uses `functionEvents/{eventHash}` as an idempotency ledger.
Its Firestore transaction updates each inbox exactly once and increments unread
counts only for recipients. It then sends high-priority Android FCM notifications
to active, non-muted devices. Successful device paths are recorded before a
retry; invalid/unregistered token documents are removed. FCM itself is
at-least-once, so Android must also de-duplicate by `messageId`. The notification
tag is `conversationId`, and data fields support authenticated deep-linking.

`onMessageDeleted` responds only to the first `deletedAt: null -> Timestamp`
transition. If the deleted message is still an inbox's newest message, its
preview becomes `This message was deleted`. Message bodies, tokens, passwords,
and notification payloads are never written to application logs.

## Local Emulator Suite

Build the packages, then start the configured Auth, Firestore, and Functions
emulators from the repository root:

```powershell
npm.cmd --prefix backend/functions run build
npm.cmd --prefix backend/admin run build
firebase emulators:start --project demo-innovfix-internal
```

Build/install the Android emulator variant explicitly with
`gradlew.bat installDebug -PfirebaseEmulator=true`. Normal debug builds default
to production Firebase so physical-device and pilot APKs never route to
`10.0.2.2` accidentally.

In another PowerShell window, seed representative employee, direct-chat, group,
reply, and reaction fixtures. The seed script refuses to run unless both
emulator variables are present:

```powershell
$env:FIREBASE_AUTH_EMULATOR_HOST = '127.0.0.1:9099'
$env:FIRESTORE_EMULATOR_HOST = '127.0.0.1:8080'
$env:GOOGLE_CLOUD_PROJECT = 'demo-innovfix-internal'
npm.cmd --prefix backend/admin run seed:emulator
```

The script prints the local-only demo accounts and password. Override that
password with `EMULATOR_SEED_PASSWORD`. Never reuse an emulator password in
production.

The callable accepts the `ENFORCE_APP_CHECK` typed deployment parameter. Use
`false` for the initial metrics pilot and `true` after confirming valid Play
Integrity traffic. The opt-in Android emulator build automatically uses the
App Check debug provider; normal debug and release builds use Play Integrity,
and the release source set cannot reference the debug provider.

## Administrator CLI

The CLI uses Application Default Credentials; it never reads a service-account
JSON key. Give the human/operator identity only the minimum Firebase Auth and
Firestore IAM roles needed, then:

```powershell
gcloud auth application-default login
npm.cmd --prefix backend/admin run build
npm.cmd --prefix backend/admin run admin -- help
```

Production mutations require both `--project PROJECT_ID` and an identical
`--confirm-project PROJECT_ID`, protecting against accidental writes to the
active gcloud project. Commands cover:

- invite an employee and generate a one-time password-setup link;
- disable/enable an employee and revoke sessions;
- assign organization `MEMBER`/`ADMIN` claims;
- create an administrator-managed group;
- add/remove group members and change group `MEMBER`/`ADMIN` roles.

Password-setup links contain a credential-like out-of-band code. Deliver them
directly to the employee; do not paste them into tickets, chat logs, or CI logs.
Disabling an employee also disables all known device-token documents. Enabling
the employee does not resurrect stale tokens; the Android app registers a fresh
token after the next sign-in.

## Verification and rollout

Run package unit tests, TypeScript builds, Firestore rules tests, and the full
Emulator Suite before deployment. Deploy first with App Check in metrics mode.
Pilot with five employees, verify Function error/retry metrics, FCM delivery,
Firestore usage, Crashlytics, and Android performance, then enforce App Check.

This v1 uses Firebase transport and at-rest protections. It is **not**
end-to-end encrypted and must not claim to be.
